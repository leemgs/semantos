\section{SemantOS}
\label{sec:semantos}

\noindent SemantOS is an end-to-end semantic reasoning framework that transforms kernel parameter tuning from a static manual process into a sustained, explainable, verifiable control loop. Figure~\ref{fig:architecture} shows the architecture, organized around four design principles: \emph{context-aware}, \emph{knowledge-centric reasoning}, \emph{safety enforcement}, and \emph{continuous adaptation}.


\subsection{Design}
\label{sec:design}

\paragraph{Design Goals.} We capture kernel signals, encode domain knowledge, emit explainable guarded updates, and preserve SLOs via staged enforcement. Guardrails are declarative policies (SLO targets, invariants, per-knob bounds) enforced by the runtime regardless of model output.

\paragraph{Components.}
The loop has five core components, each a service directory in the artifact. The \textbf{\ding{182} Telemetry Agent} collects eBPF and user-space metrics every 5\,s; the \textbf{\ding{183} Knowledge Base} stores tunable metadata, the typed dependency graph, and historical traces, autonomously refining relationships via telemetry and decayed weights. The \textbf{\ding{184} Reasoner} uses retrieval-augmented prompts to emit \textsc{knob}, \textsc{value}, \textsc{rationale}, and \textsc{uncertainty}. The \textbf{\ding{185} Safety Runtime} enforces staged rollout, monitors SLOs, and triggers veto/rollback. The \textbf{\ding{186} Operator Console} provides an explanatory interface and auditability. Algorithm~\ref{alg:control-loop} summarizes the loop.

\begin{algorithm}[t]
\caption{SemantOS Control Loop}
\label{alg:control-loop}
\begin{algorithmic}[1]
\REQUIRE Knowledge base $G$, calibration set $\mathcal{D}_{\mathrm{cal}}$, SLO bounds $\{\ell_i\}$, threshold $\tau$, decay $\gamma$
\WHILE{system is running}
  \STATE $T_t \leftarrow \textsc{TelemetryAgent.snapshot}()$ \hfill\textit{// eBPF + userspace}
  \STATE $E_t \leftarrow \textsc{KB.retrieve}(T_t, G)$ \hfill\textit{// typed graph + FAISS}
  \STATE $A_t=(\textit{changes},\textit{rationale},u,\textit{provenance}) \leftarrow \textsc{Reasoner.LLM}(T_t,E_t)$
  \IF{$u \ge \tau$ \OR $\textsc{Validate}(A_t, G, \{\ell_i\})$ fires}
    \STATE \textbf{continue} \hfill\textit{// veto: emit no-op}
  \ENDIF
  \FOR{$\textit{stage}\in\{\text{canary},\text{ramp},\text{full}\}$}
    \STATE Atomically apply all $A_t.\textit{changes}$ at $\textit{stage}$ traffic share
    \IF{regression detected on $\{\ell_i\}$}
      \STATE \textsc{Rollback}; \textsc{KB.log}($\textit{OptimizationTrace}$); \textbf{break}
    \ENDIF
  \ENDFOR
  \STATE \textsc{KB.update}$(T_t,\textit{outcome},\gamma)$ \hfill\textit{// ADWIN drift}
  \STATE Periodically refresh $\tau$ from $\mathcal{D}_{\mathrm{cal}}$ \hfill\textit{// recalibration}
\ENDWHILE
\end{algorithmic}
\end{algorithm}

\paragraph{Knowledge-Centric Decision Loop and Safety Argument.}
Each decision fuses telemetry with retrieved KB context; the uncertainty $u$ gates whether an action is approved, delayed, or rolled back, and every update carries a rationale over telemetry, KB evidence, and audit trail. Canary$\to$ramp$\to$full rollout and continuous SLO monitoring are intended to limit exposure and trigger rollback; they do not establish no-worse-than-default behavior or a drift-safety guarantee.



\subsection{Semantic Reasoning}
\label{sec:semantic}
SemantOS's semantic inference layer fuses structured domain knowledge, past experience, and LLM inference in one safe decision loop. The hybrid KB combines tunable metadata, a typed dependency graph, and a FAISS (Facebook AI Similarity Search)-powered trace store.

\noindent\textbf{Typed dependency graph.} Each node records the exact
kernel release, writable path, type, admissible range, unit, and documentation
source for a tunable. Typed edges (\textsc{depends-on},
\textsc{conflicts-with}, and \textsc{synergizes-with}) are admitted only from
run identifiers in the training partition and carry an evidence count and
source-log hashes. Pairwise interaction is estimated against additive
single-knob effects and tested on validation data. Test-family observations
never update the graph. The released seed graph is intentionally empty until
independently collected evidence passes this process; graph structure is not
presented as causal evidence.

\noindent\textbf{Graph-grounded joint reasoning.} On each invoked snapshot a composite query runs: a graph query expands the candidate knob's typed neighborhood (its \textsc{conflicts-with}/\textsc{synergizes-with} edges) into structural constraints, while vector search returns nearest-neighbor traces (prior configurations, metrics, notes) as evidence. Serialized into the prompt, this forces the Reasoner to \emph{co-tune} along synergistic edges and \emph{justify against} conflicting neighbors rather than proposing a knob in isolation, so each recommendation carries provenance to specific KB edges and traces. Using this evidence the Reasoner emits a rationale plus a calibrated uncertainty $u\!\in\![0,1]$ consumed by the safety runtime.

\subsection{Operational risk controls}
\label{subsec:risk-controls}
An evaluation window is anomalous when any pre-registered guard fires:
\[
 A_t=\mathbf{1}[L_{p95,t}>L_{\mathrm{SLO}}\lor
 C_t>C_{\max}\lor \mathrm{OOM}_t=1\lor E_t>E_{\max}].
\]
The anomaly rate is $\sum_t A_t/N_{\mathrm{windows}}$; reports retain both
counts and the denominator. An action is \emph{unsafe} when it violates a
registered guard during staged rollout. Veto and rollback are distinct: a veto
prevents application, whereas rollback restores the complete pre-transaction
snapshot after an applied bundle violates a guard.

Uncertainty thresholds are selected on the calibration split and frozen before
test. Staging and rollback limit exposure in an implementation-dependent way,
but do not guarantee safety or conformal coverage under drift. We therefore
remove the previous theorem and finite-sample proposition and report realized
unsafe-proposal, veto, rollback, and SLO-violation counts. Existing conformal
risk-control methods are relevant alternatives; SemantOS does not claim a new
general conformal method.

\paragraph{Safety Runtime Feedback.}
The \texttt{SafetyRuntime} uses $u$ with real-time SLO guards to accept, delay, or veto; rollbacks emit an \texttt{OptimizationTrace} to the KB for continual refinement and re-calibration. The matched component ablation is specified in the Evaluation protocol.

\subsection{Implementation}
\label{sec:implementation}

We implement SemantOS as a modular, Representational State Transfer (REST)-based distributed system of five containerized services that communicate via typed messages defined in \texttt{proto/semantos-control.v1.yaml}; an anonymized artifact reproduces the prototype end-to-end via \texttt{Makefile} targets.

\noindent\textbf{Services.}
\texttt{telemetry-agent/} (Python/C, eBPF) samples every 5\,s and exports \texttt{TelemetrySnapshots} ($<\!1\%$ CPU). \texttt{kb-service/} stores tunable metadata, the typed dependency graph, and traces (\texttt{RetrieveContext}, \texttt{LogOutcome}). \texttt{reasoner/} serves \texttt{/get\_recommendations} (returning an atomic \texttt{changes} array plus \texttt{rationale}, \texttt{expected\_impact}, provenance, and $u\!\in\![0,1]$), \texttt{/apply}, and \texttt{/log\_outcome}. \texttt{safety-runtime/} enforces staged rollout (canary$\to$ramp$\to$full) and rolls back when $u\!\ge\!\tau$ or guardrails fire. The optional \texttt{operator-console/} (FastAPI) surfaces telemetry, evidence, and suggestions with override/rollback controls.

\noindent\textbf{LLM training pipeline (Reasoner).}
The configured base checkpoint is
\texttt{meta-llama/Meta-Llama-3.1-8B-Instruct}; every training run must record
its resolved revision, tokenizer, trainer, and output hashes. Training is
disabled until the experiment owner supplies context--action--outcome records
and a workload-family split manifest. Train, validation, calibration, and test
families are disjoint, and a held-out family's traces and graph edges are
excluded from retrieval, adaptation, model selection, and calibration. This
identifies the intended implementation without claiming that an unverified
checkpoint or synthetic corpus produced an empirical result.

\vspace{0.6\baselineskip}
\noindent
Three core JSON endpoints (\texttt{POST~/get\_recommendations}, \texttt{/apply}, \texttt{/log\_outcome}) close the telemetry$\to$recommendation$\to$deployment$\to$feedback loop. The KB is updated via exponential decay on dependency weights ($\gamma^t$) and ADWIN drift detection. The reasoner is isolated from enforcement and runs asynchronously, so model latency cannot bypass validation. All decisions, evidence, transaction members, and rollback outcomes are logged for audit.
