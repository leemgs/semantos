\section{Introduction}
\label{sec:introduction}
Language models now act as configuration advisors: they read manuals and measurements, propose database or kernel settings, and justify each proposal in natural language~\cite{Trummer2022DBBERT,Lao2024GPTuner,Giannakouris2025LambdaTune,Chen2024AutoOS,Lin2025TuneAgent}. Such advisors are a form of evidence-grounded generation: a retrieval-augmented model~\cite{Lewis2020RAG} produces a decision together with citations and an explanation. The NLP community has developed careful methods for this setting, including citation quality~\cite{Gao2023ALCE}, attribution to identified sources~\cite{Rashkin2023AIS}, claim-level factual precision~\cite{Min2023FActScore} and explanation faithfulness~\cite{Jacovi2020Faithfulness,Turpin2023Unfaithful}. Configuration advisors, by contrast, are usually judged end to end by the performance of the configuration they choose.

End-to-end performance leaves three questions open. \emph{Added value}: does the model choose better than a conventional selector that receives the same evidence, or does it only repackage that evidence? \emph{Explanation correctness}: when an explanation cites valid evidence, does it state that evidence correctly? \emph{Reliance}: does the cited evidence actually influence the decision? A fourth question concerns acting on advice: whether a gate that screens proposals is judged by outcomes it does not itself define.

We answer these questions with an audit protocol and a testbed. The testbed, SemantOS, separates evidence (a typed interaction graph and retrieved measurement traces), proposals (an LLM that emits a complete configuration bundle with citations) and enforcement (a runtime that validates, vetoes or stages the bundle). Because the evidence is an explicit, frozen object, the same evidence can be handed to a non-LLM selector, ablated, or partially deleted; because enforcement is separate, its errors can be counted against labels computed from raw measurements.

\paragraph{Contributions.}
(i)~An audit protocol for evidence-grounded LLM advice that combines a matched-information non-LLM baseline, evidence-source ablations, cited versus matched uncited deletion, claim-level verification of explanations against the supplied evidence, and independent outcome labels, with training, retrieval, calibration and test roles frozen before test data are opened (\S\ref{sec:protocol}).
(ii)~An audit of ten LLMs on real Linux interventions, reported with every denominator (\S\ref{sec:results}). Evidence is necessary but, here, sufficient: models given the evidence match table lookup and never beat it. Explanations with valid citations frequently misreport ranges, extremes and units or overstate regularities, and deletion rarely shows citation-specific reliance.
(iii)~The SemantOS testbed with a bundle-level control contract, a class-conditional rank gate and a bounded actuator, together with released prompts, responses, annotations and logs (\S\ref{sec:testbed}). The gate result is a cautionary example of selective prediction under shift.

The task is deliberately small, one workload family on one host, and its default configuration is best, so the audit can reveal failures of added value but not successes; we make no LLM-superiority, deployment-efficacy or production-safety claim (see Limitations).
